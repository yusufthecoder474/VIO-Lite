## What was tested

The 12 CTest cases cover EuRoC-shaped parsing and missing files, sorting/duplicates, interpolated IMU endpoints and source gaps, invalid numbers, camera calibration, blank/zero-baseline tracking rejection, actual LK/RANSAC on rendered nonplanar translation at both 0.18 and 0.075 synthetic distance units, transform inversion/composition, known scale 2.5 with nonzero starting velocity and a large outlier, unobservable/negative-scale windows, CSV shape, gravity removal/gyro integration, and quiet/dynamic initialization.

The eight Python cases cover rigid rotation/translation, refusal to fit metric scale, explicit Sim(3) behavior, integer-nanosecond association, gap rejection, degenerate alignment, camera lever-arm conversion using ground-truth orientations, and a full evaluator test proving that ground truth cannot fill missing metric scale even when Sim(3) diagnostic alignment succeeds.

Smoke data is generated by `scripts/make_smoke_data.py`: 31 rendered camera frames at 20 Hz and 301 IMU rows at 200 Hz. Ten frames form the initialization prefix, leaving 21 output poses / 20 attempted pairs. The fixture has a stationary prefix followed by constant-speed camera motion, fixed orientation and gravity-only IMU measurements. It does not simulate a realistic acceleration impulse at the transition; it is an I/O and numerical-degeneracy smoke fixture, not a physically complete sensor simulator. There is no ground-truth file in this run.

The smoke run is expected to reject metric scale: there is no acceleration excitation to establish scale. All numerical results above are read from the actual final run. Timing excludes startup, CSV loading, initialization and final writes; it includes attempted pair processing. It is not a EuRoC performance benchmark.

## Host and dependency setup

Host: Linux x86_64, Python 3.12.14, NumPy 2.3.5. The initial image contained GCC but no CMake or OpenCV development headers. Ubuntu package downloads succeeded using a workspace cache; packages were extracted under `native-deps/` because the managed environment's system package directory could not be installed into normally. They are not bundled in the deliverable.

The exact build route used this local prefix (paths relative to the parent of VIO-Lite):

```bash
export LD_LIBRARY_PATH="$PWD/native-deps/usr/lib:$PWD/native-deps/usr/lib/x86_64-linux-gnu:$PWD/native-deps/usr/lib/x86_64-linux-gnu/blas:$PWD/native-deps/usr/lib/x86_64-linux-gnu/lapack"
native-deps/usr/bin/cmake -S VIO-Lite -B build-vio -DCMAKE_BUILD_TYPE=Release \
  -DVIO_OPENCV_PREFIX="$PWD/native-deps/usr" \
  -DEigen3_DIR="$PWD/native-deps/usr/share/eigen3/cmake"
native-deps/usr/bin/cmake --build build-vio --clean-first -j2
native-deps/usr/bin/ctest --test-dir build-vio --output-on-failure
python3 VIO-Lite/scripts/test_evaluation.py -v
python3 VIO-Lite/scripts/run_project.py --skip-build \
  --executable "$PWD/build-vio/vio_lite" \
  --output "$PWD/VIO-Lite/evidence/smoke"
```

For a regular Ubuntu machine, use the standard package installation and build commands in the README instead. The archive contains source and evidence, not the host's dependency extraction or compiled binaries.

The clean Release build emits GCC `-Wmaybe-uninitialized` diagnostics within Eigen's `Quaternion::FromTwoVectors` SVD implementation. Build and tests completed successfully; warnings are retained in `build.log`. No sanitizer claim is made.

## Defect fixed during execution

The first application run tracked only 3 / 20 pairs. OpenCV's default `recoverPose` far-point cutoff rejected many small-baseline synthetic correspondences. Raising that cutoff to 1,000 baseline units, while retaining the separate angular-parallax check, produced 20 / 20 tracked pairs. A small-baseline image regression check is now part of the tracking CTest case. This is a fix established on synthetic inputs, not an accuracy improvement on recorded data.
